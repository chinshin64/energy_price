# 证据中心迭代产品方案

## 1. 背景

当前页面采集、请求采集和小规模访问验证都会产生证据，但证据分散在任务过程、报告详情和数据校验结果中。证据中心的目标是把这些材料统一管理，让用户能快速判断一次验证是否可复核、是否可归档、是否需要复测。

## 2. 产品目标

证据中心需要支持：

- 按报告、任务、平台、城市查看证据。
- 按证据类型判断完整性。
- 把证据引用到蓝军验证报告。
- 对证据缺口给出下一步动作。
- 支持复测时继承原证据和风险发现。

## 3. 证据类型

证据中心按五类组织：

| 证据类型 | 内容 |
| --- | --- |
| 页面证据 | 截图、页面文本、页面操作过程 |
| 请求证据 | 请求摘要、响应摘要、请求数量、失败原因 |
| 数据证据 | 入库结果、字段完整率、城市匹配结果 |
| 环境证据 | 微信窗口、记录服务、网络出口、数据库状态 |
| 复测证据 | 修复后重新执行的结果和结论变化 |

面向用户时展示证据名称、用途、状态和复核建议，不暴露内部文件名或存储路径。

## 4. 报告生命周期

报告状态包括：

| 状态 | 含义 |
| --- | --- |
| 草稿 | 已创建，正在收集证据 |
| 执行中 | 验证任务正在进行 |
| 待复核 | 证据已生成，需要人工确认 |
| 已完成 | 结论已确认 |
| 待复测 | 发现风险，需要修复后复测 |
| 已归档 | 报告完成并冻结 |

已归档报告不得被覆盖。复测应生成新版本，并保留和原报告的关联关系。

## 5. 页面能力

### 报告列表

列表页支持：

- 按能力类型筛选：页面采集、请求采集、小规模访问验证。
- 按平台、城市、结论、风险等级筛选。
- 展示报告编号、标题、城市数、结论、风险等级、创建时间。
- 快速进入详情、下载脱敏报告、创建复测。

### 报告详情

详情页支持：

- 报告摘要。
- 城市结论。
- 证据矩阵。
- 风险发现。
- 修复建议。
- 复测记录。

### 证据详情

证据详情展示：

- 证据类型。
- 证据状态。
- 关联城市和任务。
- 摘要内容。
- 脱敏检查状态。
- 下一步动作。

## 6. 证据完整性规则

页面采集至少需要：

- 页面状态。
- 页面截图或文本。
- 操作过程。
- 入库校验。

请求采集至少需要：

- 请求记录服务状态。
- 目标请求数量。
- 请求摘要。
- 解析和入库结果。

小规模访问验证至少需要：

- 授权范围。
- 请求材料状态。
- 请求结果摘要。
- 网络出口命中情况。
- 数据校验结果。

缺少关键证据时，报告结论不得标记为通过。

## 7. 复测流程

复测流程：

1. 从原报告创建复测任务。
2. 自动继承目标范围、风险发现和证据缺口。
3. 执行复测并生成新证据。
4. 对比原结论和复测结论。
5. 形成复测报告并关联原报告。

复测不能覆盖原报告。

## 8. 安全与脱敏

证据中心默认只展示脱敏内容。

不得展示：

- 账号凭证和会话凭据。
- 网络出口认证信息。
- 完整请求内容。
- 完整响应内容。
- 可识别个人或账号身份的敏感字段。

完整版材料只允许在授权安全排障场景中查看，并记录审计日志。

## 9. 验收标准

- 用户能从报告详情判断证据是否完整。
- 每条风险发现都能定位到证据或证据缺口。
- 报告下载默认脱敏。
- 复测报告不会覆盖原报告。
- 证据中心不展示内部文件路径、服务路由或代码字段。
