# 请求采集自动操控与入库工作流

## 1. 目标

把请求采集做成一个闭环任务：系统启动请求记录服务，自动操控已授权桌面小程序，触发目标业务请求，停止记录，解析结果并写入数据中心。

## 2. 用户流程

```text
选择平台和目标城市
  -> 点击自动采集并入库
  -> 系统检查请求记录服务和小程序页面状态
  -> 自动操作小程序
  -> 记录目标业务请求
  -> 解析请求记录
  -> 写入数据中心
  -> 展示证据和下一步
```

## 3. 结果必须分阶段展示

不能只写“完成”。页面和报告必须拆开：

- 小程序是否可操作。
- 请求记录服务是否启动。
- 是否记录到目标业务请求。
- 请求记录是否可解析。
- 数据是否写入数据中心。
- 是否需要重新操作或人工处理。

## 4. 安全边界

- 只处理已授权的小程序会话。
- 不绕过登录、授权、验证码、证书固定或平台访问控制。
- 不生成凭证材料、会话材料或未知校验材料。
- 请求证据默认脱敏。

## 5. 验收标准

| 场景 | 预期 |
| --- | --- |
| 准备状态查询 | 只检查条件，不启动采集 |
| 手动请求采集 | 可以开始和停止请求记录服务 |
| 自动采集入库 | 返回页面操作、请求记录、解析、入库四段证据 |
| 未记录到目标请求 | 显示明确原因和下一步 |
| 入库失败 | 不把请求记录成功误写为整体成功 |

## 6. 自检

- 产品口径是“请求采集”，不是技术组件演示。
- 自动操控、请求记录、解析和入库必须独立展示状态。
- 真实成功必须以目标业务请求和入库结果为证据。
