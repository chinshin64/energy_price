## 一、核心结论

本报告以滴滴能源为自评主体，用六家行业平台校准我们的真实安全位置。采用“当前服务器真实执行并有动态证据，才能评为强”的修正口径后，滴滴能源综合安全得分为 49 分、批量获取风险为 56 分，当前仍暂列第 1。请求校验和安全准备已有真实证据，但服务器临时核验、真实设备识别、身份强制和登录状态失效仍未完整验证，因此排名不代表“已经安全”。

- **滴滴的有效能力**：已经验证防止请求冒充、访问前安全准备、持续更新登录状态和完整场站查询流程，历史请求被直接重复使用的价值低于无需登录或长期使用同一凭证的平台。
- **滴滴的核心短板**：真实设备标识验证尚未完成，本次小范围测试未触发服务器临时核验，部分历史测试缺少逐次请求的成功失败记录。
- **行业对标启示**：匿名接口是最高风险模式；客户端加密和可复用会话只能增加分析成本。滴滴下一步应把设备可信和行为风险接入核心查询，而不是继续堆叠客户端复杂度。

### 2. 滴滴能源发现的主要问题

1. **滴滴最高优先级**：尚未证明核心场站查询一定会识别真实设备。
2. **滴滴最高优先级**：放在客户端的请求校验和临时核验方法可能被分析出来，关键判断必须依赖服务器当次生成、很快失效的信息。
3. **滴滴高优先级**：服务器临时核验缺少真实触发后的逐次请求证据。
4. **滴滴高优先级**：历史测试缺少请求次数、成功失败分布、来源网络和停止原因。
5. **行业发现**：云快充、快电、团油的匿名查询模式形成最低批量门槛。
6. **行业发现**：特来电、星星充电、新电途说明加密不能替代短时身份、设备绑定和行为风控。

### 3. 下一步建议

- **2 周内**：记录正常设备基线，确认核心场站查询是否真的使用设备风险结果，并明确负责团队。
- **30 天内**：将账号、设备、来源网络、访问频率、翻页和跨区域查询行为纳入核心查询判断，统一拒绝、减少返回内容和限速规则。
- **90 天内**：建立安全准备、服务器临时核验、设备绑定和异常遍历月度复测，形成逐次请求证据、风险指标和管理层验收看板。

## 二、测试概述

### 1. 背景和目的

评估滴滴能源核心场站数据接口的真实防护，判断当前优势是否来自可持续的服务端控制，并用六家行业平台识别我们的短板和建设优先级。

### 2. 测试范围

以滴滴能源为自评主体，对标云快充、快电、团油、特来电、星星充电和新电途的只读场站/油站查询链路，检查身份、请求防伪、加密、动态校验、设备可信、会话和反自动化能力。

### 3. 测试方法

- 客户端包和安全 SDK 静态分析。
- 授权 HAR 请求/响应对照。
- 签名、加解密和状态机离线验证。
- 172/本地受控低频请求与真实业务结果复核。
- 证据分为“运行验证、条件验证、仅代码分析”，未知项不以推测替代。

完整测试记录见同目录的 `platform-security-continuous-test-report.html`。当前共回填 17 条历史记录，逐条保留测试时间、测试方案、测试路径、原理、测试环境、测试内容、成功点、失败点、成功率、停止原因和证据缺口；后续测试继续通过追加脚本写入，不覆盖历史结果。

## 三、滴滴自身能力与行业深度对标

### 滴滴能源自身安全能力

滴滴能源当前综合安全得分 49 分、批量获取风险 56 分，在本次七平台样本中暂列第 1。请求防冒充已经动态验证；访问前安全准备和连续登录状态属于部分验证；传输内容额外保护已确认较弱；服务器临时核验没有真实在线触发；真实设备识别尚未证明作用于核心查询。

当前结论仍有四个边界：核心查询是否强制确认真实用户、是否使用真实设备风险结果、服务器临时核验能否在线完成、登录状态何时失效及是否绑定设备，均需动态对照。因此，现阶段应把“第 1 名”理解为相对位置，不应视为安全建设完成。

### 滴滴自身卷宗与行业观察

### 云快充

- **策略**：场站查询为明文 JSON，当前查询链路未观察到签名、token 或设备态要求。
- **优势**：链路简单、兼容性高、业务可用性好。
- **问题**：匿名读取、缺少完整性保护、缺少会话绑定和服务端挑战。
- **改进**：场站核心字段采用服务端签发、短时间有效的访问凭证；绑定 appid/场景/区域；增加速率与遍历检测；对高价值字段分级返回。

### 快电

- **策略**：静态 appKey/appSecret 参与 MD5；公共字段包含设备/传感标识，但匿名 token 可查询。
- **优势**：具备基础请求完整性校验和公共参数体系。
- **问题**：秘密位于客户端、匿名核心接口、设备字段可为空、明文响应。
- **改进**：移除客户端长期秘密；改为服务端短时访问凭证；核心查询强制有效会话；设备字段与服务端风险分绑定。

### 团油

- **策略**：与快电同构 MD5，携带 shumeiID，但当前油站查询可使用空 token。
- **优势**：已有设备标识和公共参数结构。
- **问题**：同源签名导致横向复用；静态 shumeiID 可重放；匿名查询；明文响应。
- **改进**：按业务独立密钥体系；设备标识挑战化并短时化；服务端验证 token/场景；增加地理遍历和分页速率检测。

### 特来电

- **策略**：SVER、防篡改、两阶段 AES-CBC 请求/响应、gzip、C01 和 RefreshToken。
- **优势**：双向保护完整，协议分析成本明显高于匿名平台。
- **问题**：关键算法和密钥可从客户端恢复；RefreshToken 生命周期过长；窗口内可脱离微信运行时。
- **改进**：RefreshToken 缩至小时/天级并轮换；密钥由服务端短时派生；高频查询触发二次设备校验；刷新链路绑定设备和账号风险。

### 星星充电

- **策略**：双重 MD5、SM2 请求加密、openId/x-uid 绑定，响应明文。
- **优势**：微信身份绑定和非对称加密能阻止完全匿名调用。
- **问题**：签名没有服务端秘密；openId 可被缓存复用；响应缺少保护；设备状态较弱。
- **改进**：openId 叠加短时服务端访问凭证；签名加入服务端一次性随机数；响应高价值字段分级；建立 openId/设备/IP/行为联合画像。

### 滴滴能源（自身基线）

- **当前策略**：我们会检查请求是否被冒充，由服务器在必要时临时核验，持续更新登录状态，并借助微信安全组件识别设备风险。
- **已验证优势**：访问前安全准备和场站查询完整流程已跑通；服务器每次生成不同状态并持续更新登录信息，降低了历史请求被直接重复使用的价值。
- **自身问题**：请求校验和临时核验的处理方法仍可从客户端分析出来；真实设备标识是否进入核心场站查询的服务器判断尚未证实；真实临时核验和部分历史测试缺少逐次请求证据。
- **我们的改进**：优先确认核心场站查询会使用设备风险结果；临时核验严格绑定账号、设备、接口、时间和服务器当次状态；把来源网络、翻页、跨区域遍历和行为轨迹纳入统一限速与减少返回内容规则。

### 新电途

- **策略**：会话材料派生对称密钥，摘要字段校验请求完整性，请求与响应均加密；当前已有一次完整还原的真实业务结果。
- **优势**：双向数据保护增加直接观察和篡改成本；会话派生材料比纯固定密钥更能阻止无状态重放。
- **问题**：已有业务结果只证明授权材料可以驱动业务查询；全新登录、安全准备、请求数量、执行节点、材料有效期和设备绑定均未留存完整证据。
- **改进**：新会话初始化绑定真实用户、设备和短时服务端票据；改用 AEAD；补齐凭证轮换、重复请求检测和请求级审计。

## 四、滴滴能源建议和路线图

### 30 天：补齐核心接口的设备可信闭环

- 完成真实设备风险标识的正常参考值采集，验证场站查询是否实际使用设备风险结果。
- 为核心接口明确安全、风控和业务研发负责人，记录每次验证的请求级状态、出口、停止原因和证据文件。
- 上线分页、地理遍历、异常调用频率和跨区域跳变的基础监控。
- **验收标准**：正常设备链路稳定可用；伪造、缺失、过期或跨账号复用的设备状态能够被识别、降级或拒绝。

### 60 天：把动态挑战升级为服务端风险决策

- 将账号、设备、IP、网络连接特征、接口、地理位置和行为序列纳入联合评分。
- 让挑战结果严格绑定当前会话、接口上下文和短时服务端状态，明确一次性使用和超时规则。
- 对异常分页、重复请求、跨城市扫描和高频失败实施统一限速、挑战、字段降级和阻断。
- **验收标准**：单个客户端算法被恢复后，仍不能绕过服务端状态、设备绑定和行为策略形成稳定批量链路。

### 90 天：建立持续验证和管理闭环

- 建立安全准备、服务器临时核验、设备绑定、异常遍历和登录材料生命周期的自动化月度回归。
- 持续跟踪行业平台的匿名访问、长期凭证、客户端秘密和设备绑定变化，用于校准自身优先级。
- 建立管理看板，固定展示最高和高优先级问题、责任人、完成标准、请求级证据、趋势和复测结果。
- **验收标准**：新增或变更接口自动进入安全基线；问题能够从发现、整改、复测到关闭全程留痕。

## 五、附录：名词释义

| 名词 | 易懂解释 |
|---|---|
| 综合安全得分 | 0–100 分，越高越安全；综合考虑技术防护完整度和批量利用难度。 |
| 批量利用风险 | 0–100 分，越高越危险；表示把单次验证扩展成长期、批量能力的难易程度。 |
| 技术防护能力 | 原报告中的“D 分”，衡量身份、签名、加密、动态校验、设备和会话六方面。 |
| 平台声称可查询的总量 | 平台某次响应中给出的总数，不等于实际请求次数，也不代表本次取得的数量。 |
| 接口链路已验证 | 已在授权环境真实执行关键步骤并得到业务响应，不代表可以无限调用。 |
| 匿名查询已验证 | 没有有效用户登录凭证也能获取核心列表。 |
| 仅代码分析 | 只看到了客户端算法和流程，尚未用当前服务端完成动态验证。 |
| 短时服务端访问凭证 | 服务端临时签发、几分钟内失效并绑定业务场景的“临时通行证”。 |
| 动态挑战 | 服务端临时出题，客户端必须根据当前会话在短时间内作答。 |
| 设备指纹 | 根据设备和运行环境生成的风险标识，不是简单的 UA 字符串。 |
| RefreshToken | 用于换取新访问凭证的长期钥匙；寿命越长、设备绑定越弱，风险越大。 |
| nonce / 一次性随机数 | 每次请求只能使用一次的随机编号，用于阻止历史请求被原样重复发送。 |
| AEAD | 同时防止数据被看懂和被篡改的现代加密方式。 |
| 工程化规模能力 | 加入批量任务、失败重试、监控、数据质量和凭证维护后的持续运行能力。 |

## 限制与合规

本报告内容敏感，仅用于滴滴能源内部授权安全评估。禁止对外发送、公开展示、复制传播或用于未经授权的测试。评分和时间是区间估计，会受版本、账号、网络、风控策略和验证环境影响。报告不包含密钥、完整 token、签名代码、原始请求或可直接执行的批量调用脚本。
