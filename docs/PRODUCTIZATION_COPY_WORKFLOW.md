# 产品化文案工作流

## 1. 目标

让当前系统面向业务运营、安全审核和产品使用者可读。用户看到的页面和文档应围绕页面采集、请求采集、小规模访问验证、证据、结论和下一步动作展开；内部组件名只保留在开发附录、排障日志和服务路径说明中。

## 2. 范围

本工作流覆盖：

- 主工作台页面文案。
- 状态提示、按钮、占位文案和失败原因。
- 报告列表、报告详情和证据中心。
- 产品说明、设计文档、历史方案和部署说明。
- 图示、报告模板和验收清单。

不在本轮范围内：

- 改数据库结构。
- 改后端行为。
- 改服务返回字段。
- 删除开发人员必须使用的服务路径。

## 3. 文案规则

| 内部表达类型 | 用户表达 |
| --- | --- |
| 第一类页面读取链路 | 页面采集、页面识别 |
| 第二类请求记录链路 | 请求采集、请求记录服务、请求记录文件 |
| 第三类低频验证链路 | 小规模访问验证、请求材料 |
| 服务调用和路径 | 业务请求、访问、服务能力 |
| 出口和访问路径 | 网络出口 |
| 凭证和校验材料 | 凭证材料、请求材料 |
| 环境检查 | 准备状态 |
| 失败原因 | 当前阻塞、下一步 |
| 智能能力 | 智能助手、模型服务信息 |

## 4. 已完成范围

- 主工作台导航、三种能力卡片、状态提示和主要按钮。
- 报告列表、报告详情、证据中心和下载文案。
- 项目入口文档、架构说明、服务能力速查和测试说明。
- 图示说明和三张能力图。
- 报告版式、蓝军报告设计、请求记录中心设计。
- 请求材料健康、材料安全评估、证据中心迭代方案。
- 小规模访问验证智能异常处理和系统级智能助手设计。
- 历史 workflow、部署说明、远端验证报告和待办差距清单。
- 手机交互控制和请求采集自动入库说明。

## 5. 仍需持续关注

- 前端代码中的内部变量名和服务路径不等同于用户文案，但新增页面时要避免直接渲染它们。
- 历史报告样例如果展示给业务人员，需要套用脱敏和产品化规则。
- 开发附录可以保留服务路径，但正文必须先解释业务含义。
- 任何“执行成功”都要拆成准备、记录、解析、入库和证据状态。

## 6. 自检规则

1. 普通用户是否知道下一步该做什么。
2. 文案是否误导用户以为可以绕过登录、授权或平台访问控制。
3. 证据是否区分记录、解析、入库和报告归档。
4. 多城市任务是否保留每城市结论。
5. 敏感信息是否默认脱敏。

## 7. 验收门禁

- 前端脚本语法检查通过。
- 图示资源可以重新生成。
- 文档和页面没有空白格式错误。
- 产品文档中不再出现旧链路名称、内部路径、调试字段或未脱敏样例。
- 172 远端文件和本机文件哈希一致。
