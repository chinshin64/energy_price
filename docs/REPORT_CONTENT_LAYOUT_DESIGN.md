# 报告内容与页面布局方案

## 1. 目标

报告详情页要让安全工程、产品负责人和业务复核人快速看懂三件事：

- 这次验证覆盖了什么对象、城市和范围。
- 证据是否完整，结论是否可信。
- 发现了什么风险，下一步如何修复或复测。

页面不展示内部服务路径、开发字段、原始请求内容或调试代码。需要排障的完整信息放在受控开发附录或审计入口中。

## 2. 首页摘要区

摘要区放在第一屏，包含：

- 报告名称。
- 报告编号。
- 验证对象。
- 能力类型：页面采集、请求采集、小规模访问验证。
- 城市范围。
- 总体结论。
- 风险等级。
- 证据完整性。
- 复测状态。

摘要区使用状态徽标表达结论：

| 状态 | 展示语义 |
| --- | --- |
| 通过 | 证据完整，未发现目标风险 |
| 部分通过 | 部分城市或部分证据仍需复核 |
| 失败 | 目标风险或关键异常成立 |
| 阻塞 | 环境或权限条件不足，无法得出结论 |
| 待复测 | 已发现问题，等待修复后复验 |

## 3. 测试对象区

测试对象区展示：

- 平台名称。
- 业务线。
- 城市和地标范围。
- 授权半径或目标范围。
- 执行模式：串行、并发、人工辅助。
- 执行人或系统任务。

平台内部标识只作为后台字段，不在普通页面中展示。

## 4. 能力说明区

能力说明区用产品语言解释验证能力：

- 页面采集：按普通用户视角读取小程序页面。
- 请求采集：通过小程序真实操作记录业务请求证据。
- 小规模访问验证：在授权范围内验证目标数据访问风险。

说明区不展示请求名称、内部引用编号或文件路径。

## 5. 城市结论区

每个城市独立展示：

- 城市和地标。
- 执行状态。
- 证据数量。
- 入库数量。
- 字段完整性。
- 失败原因。
- 复测建议。

总体结论必须由城市结论聚合，不能只保留汇总文字。

## 6. 证据矩阵区

证据矩阵按证据类型展示完整性：

| 证据类型 | 说明 |
| --- | --- |
| 页面证据 | 截图、页面文本、页面操作过程 |
| 请求证据 | 请求摘要、响应摘要、请求数量、失败原因 |
| 数据证据 | 入库数量、字段完整率、城市匹配情况 |
| 环境证据 | 微信窗口、记录服务、网络出口、数据库状态 |
| 复测证据 | 修复后重新执行的结果 |

证据状态使用“完整、部分缺失、缺失、阻塞”表达。

## 7. 风险发现区

每条风险发现包含：

- 风险标题。
- 风险等级。
- 影响范围。
- 证据引用。
- 当前状态。
- 修复建议。
- 复测要求。

高风险发现必须至少引用两类证据。如果证据不足，应明确写出缺口，而不是给出确定结论。

## 8. 脱敏与完整信息

页面默认使用脱敏模式。

脱敏模式展示：

- 请求功能描述。
- 参数数量和是否包含凭证材料。
- 模糊坐标。
- 脱敏后的网络出口说明。
- 脱敏后的执行节点。

完整信息只允许在授权排障或安全复核场景中查看，并需要记录审计日志。

不得在普通页面展示：

- 账号凭证和会话凭据。
- 完整请求内容。
- 完整响应内容。
- 网络出口认证信息。
- 可识别个人或账号身份的敏感字段。

## 9. 下载设计

下载入口默认生成脱敏报告。

下载弹窗应提供：

- 报告格式：归档报告、复核材料。
- 内容版本：审核版、完整版。
- 完整版风险提示。
- 审计确认。

审核版用于跨团队分享和归档。完整版只用于内部安全排障，并记录操作人、时间和报告编号。

## 10. 兼容旧报告

旧报告进入新版页面时，应在展示层做兼容转换：

- 缺少城市子结论时，根据报告范围生成待复核城市项。
- 缺少证据矩阵时，根据已有证据引用生成基础矩阵。
- 完整执行节点在展示时脱敏。
- 复测状态统一映射为待复测、复测中、复测通过或复测失败。

兼容转换不得修改原始归档材料。

## 11. 页面行为

页面应支持：

- 报告状态徽标。
- 城市级展开和收起。
- 证据矩阵筛选。
- 风险发现跳转到对应证据。
- 一键创建复测任务。
- 脱敏下载。

页面不展示内部数据结构、服务路径或代码示例。

## 12. 设计原则

1. 报告证明验证做过、证据可信，而不是指导用户复现内部操作。
2. 默认展示结论和证据摘要，敏感细节受控查看。
3. 数字摘要优先于逐条暴露明细。
4. 城市结论优先于总体口号。
5. 旧报告兼容在展示层完成，不影响归档材料。
