## 一、报告内容模块定义

### 章节结构（通用框架，三种测试方式共用）

| 序号 | 章节 | 必填 | 默认状态 | 说明 |
|------|------|------|----------|------|
| 1 | 安全声明 | ✅ | 展开 | 报告首屏，声明脱敏策略和访问边界 |
| 2 | 报告摘要 | ✅ | 展开 | 结论、风险等级、证据完整性、复测状态 |
| 3 | 测试对象与范围 | ✅ | 展开 | 平台、城市、地标、半径、资产范围（脱敏） |
| 4 | 测试方式与原理 | ✅ | 展开 | 工作原理流程图 + 证据引用 |
| 5 | 多城市测试结论 | ✅ | 展开 | 每城市独立结论 + 指标表格 |
| 6 | 风险发现 | ✅ | 展开 | 发现列表，复现步骤默认折叠 |
| 7 | 证据矩阵 | ✅ | 展开 | 类型 × 状态 × 用途 |
| 8 | 数据质量指标 | 选填 | 展开 | 字段完整率、城市匹配率、去重率 |
| 9 | 出站证据明细 | 选填 | **折叠** | 脱敏后的请求摘要，最高安全风险区域 |
| 10 | 修复建议 | ✅ | 展开 | 优先级排序的行动项 |
| 11 | 复测状态 | ✅ | 展开 | 复测标准、原报告引用、子报告链接 |
| 12 | 附录 | 选填 | **折叠** | HAR摘要、OCR行、截图、原始日志 |

### 方式特有模块

| 测试方式 | 额外必填模块 | 额外选填模块 |
|----------|-------------|-------------|
| 页面自动化 | 手机设备信息、AI监督事件 | 截图证据、OCR质量报告 |
| 后台自动化 | 录包服务状态、HAR来源 | 模板学习统计、会话日志 |
| 流量自动化 | 请求预算统计、代理出口分布 | AI修复事件、参数补丁记录 |

## 二、字段级内容规范

### 必填字段

| 字段 | 格式 | 示例 | 脱敏规则 |
|------|------|------|----------|
| 报告编号 | BTR-YYYYMMDD-NNNN | BTR-20260608-0001 | — |
| 报告标题 | 中文描述 | 多城市场站数据暴露风险验证报告 | — |
| 测试方式 | page-automation / background-automation / traffic-template | traffic-template | — |
| 平台 | 平台标识 | didi-charging | — |
| 城市列表 | 中文城市名数组 | ["武汉", "南京", "苏州", "桂林"] | — |
| 总体结论 | passed / partial / failed / blocked | partial | — |
| 风险等级 | high / medium / low / none | medium | — |
| 证据完整性 | complete / partial / missing | partial | — |
| 复测状态 | none / pending / in-progress / done | pending | — |

### 必须脱敏的字段

| 字段 | 原始值示例 | 脱敏后 | 规则 |
|------|-----------|--------|------|
| API URL | `https://energy.xiaojukeji.com/station-api/homepage/stationList` | `energy.xiaojukeji.com/station-api/**/**List` | 保留域名+一级路径，后续路径用`**`替代 |
| 接口名 | `stationList`, `getoneinfo` | `列表接口`, `详情接口` | 用功能描述替代技术名 |
| 参数键名 | `queryKeys: ["source","ttid","wsgsig","openid"]` | `"queryParamCount": 4, "hasAuthParams": true` | 只保留计数和是否含认证参数 |
| 认证参数名 | `openid`, `token`, `tokenId`, `ticket`, `wsgsig` | 移除 | 从任何可见列表中移除 |
| 内网 IP | `172.23.32.250` | `172.23.x.x` | 遮蔽后两段 |
| 代理地址 | `http://user:pass@47.111.139.230:50180` | 不展示 | 报告中不出现 |
| 精确坐标 | `30.5928, 114.3055` | `30.59xx, 114.30xx` | 保留2位小数+xx |
| 平台指纹头 | `xweb_xhr` | `redacted` | 微信特有标识需遮蔽 |

### 补充展示的统计字段（当前缺失）

| 统计项 | 说明 | 格式 |
|--------|------|------|
| 响应状态码分布 | 证明请求发生了什么 | `200: 20次, 501: 2次` |
| 代理出口分布 | 证明代理策略 | `直连: 22次, 默认代理: 0次` |
| 证据文件 hash | 证明证据未被篡改 | SHA-256 前8位 |
| 数据质量量化 | 字段完整率、匹配率 | `地址完整率: 87%, 城市匹配率: 100%` |

## 五、v1 报告兼容方案

现有 BTR-RISK-20260531-0001 是 v1 格式，新版式需兼容展示：

| v1 字段 | v2 对应 | 兼容处理 |
|---------|---------|----------|
| 无 `targets` 数组 | `targets`（每城市子结论） | 从 `scope` 解析城市名，状态标记为 `unknown` |
| 无 `events` 数组 | `events` | 空数组 |
| `retestStatus` 扁平字段 | `retest.status` | 迁移到嵌套结构 |
| `methods[].evidenceRefs` 为字符串 | `evidenceMatrix` 结构化 | 保留原引用但标记为 `legacy` |
| `executor.node` 完整 IP | 脱敏后展示 | 展示时遮蔽，不改原文件 |

兼容原则：v1 报告的原始 `report.json` 不做修改，只在读取和展示时做兼容转换。

## 六、脱敏选项设计

### 6.1 脱敏模式

系统提供两种脱敏模式，在 **查看** 和 **下载** 两个场景均可切换：

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| 🛡️ 脱敏模式（默认） | 接口地址、参数结构、认证字段、精确坐标、内网IP 等敏感信息遮蔽 | 日常审核、跨团队分享、归档 |
| 🔓 完整模式 | 展示原始数据，不做任何遮蔽 | 问题排查、技术复测、内部安全团队使用 |

### 6.2 查看场景

#### 前端详情页脱敏切换

- 页面顶部提供 **脱敏开关**（Toggle），默认开启脱敏模式
- 切换时无需重新请求接口，前端对已加载数据实时切换渲染
- 切换到完整模式时，弹出确认提示："完整模式将展示接口地址、参数结构等敏感信息，请确认使用场景"

```
┌─────────────────────────────────────────────┐
│  🛡️ 脱敏模式 [开/关]     ← 全局切换开关     │
├─────────────────────────────────────────────┤
│                                             │
│  脱敏模式 ON 时：                            │
│    接口名 → "列表接口" / "详情接口"           │
│    URL → "energy.xiaojukeji.com/station-api/****"  │
│    参数 → "查询参数 4 个（含认证参数）"        │
│    坐标 → "30.59xx, 114.30xx"               │
│    IP → "172.23.x.x"                        │
│                                             │
│  脱敏模式 OFF 时：                           │
│    接口名 → "stationList" / "getoneinfo"     │
│    URL → 完整地址                            │
│    参数 → 完整键名列表                        │
│    坐标 → 精确经纬度                         │
│    IP → 完整内网地址                         │
│                                             │
└─────────────────────────────────────────────┘
```

#### 各区域在两种模式下的展示差异

| 区域 | 脱敏模式 | 完整模式 |
|------|----------|----------|
| 报告摘要 - 资产范围 | 列表接口、详情接口 | stationList、getoneinfo |
| 测试方式 - 证据引用 | 录包服务状态、业务HAR | capture-recorder-status、business-har-pending |
| 风险发现 - 影响面 | 列表接口、详情接口 | stationList、getoneinfo |
| 证据矩阵 - 引用路径 | 脱敏路径 | 实际文件路径 |
| 出站证据明细 | 脱敏请求摘要（计数+状态码） | 完整URL、参数键名、精确坐标 |
| 执行器节点 | 172.23.x.x | 172.23.32.250 |
| 安全声明 | 显示 | 显示（标注当前为脱敏/完整模式） |

### 6.5 API 设计

#### 查看场景

详情接口增加查询参数控制脱敏：

```
GET /api/blue-team/reports/:id?sanitize=true   ← 默认，返回脱敏数据
GET /api/blue-team/reports/:id?sanitize=false   ← 返回完整数据

GET /api/blue-team/reports/:id/evidence/:type/:filename?sanitize=true   ← 默认
GET /api/blue-team/reports/:id/evidence/:type/:filename?sanitize=false  ← 完整
```

- `sanitize=true`（默认）：后端返回脱敏后的数据，前端可直接渲染
- `sanitize=false`：后端返回原始数据，前端需用户确认后才请求

#### 下载场景

```
GET /api/blue-team/reports/:id/download?format=markdown&sanitize=true   ← 默认
GET /api/blue-team/reports/:id/download?format=json&sanitize=false      ← 完整版
```

- `sanitize=true`（默认）：下载脱敏后的文件
- `sanitize=false`：下载完整版文件，后端记录审计日志

### 6.6 前端状态管理

```javascript
// 报告详情页状态
const reportState = {
  sanitizeMode: true,        // 脱敏模式开关，默认 true
  currentReport: null,       // 原始报告数据（始终从完整数据接口获取）
  displayReport: null,       // 当前展示的报告数据（根据 sanitizeMode 计算）
};

// 切换脱敏模式时
function toggleSanitize(enabled) {
  if (!enabled) {
    // 切换到完整模式，弹出确认
    showConfirm('完整模式将展示接口地址、参数结构等敏感信息，请确认使用场景', () => {
      reportState.sanitizeMode = false;
      reportState.displayReport = applySanitize(reportState.currentReport, false);
      renderReport();
    });
  } else {
    reportState.sanitizeMode = true;
    reportState.displayReport = applySanitize(reportState.currentReport, true);
    renderReport();
  }
}

// 脱敏函数（纯前端计算，无需重新请求）
function applySanitize(data, sanitize) {
  if (!sanitize) return data;
  // 按脱敏规则映射表转换
  return sanitizeReport(data);
}
```

## 七、核心设计原则

1. **报告证明"测试做了"，不让人"照着做一遍"** — 保留结构和结论，遮蔽操作细节
2. **数字比枚举更安全** — 状态码分布 > 逐条列出，参数计数 > 参数名清单
3. **折叠是安全边界** — 出站证据和附录默认折叠，主动查看=明确意图
4. **v1 不改原文件** — 兼容在展示层做，原始数据不动
5. **三种方式通用框架 + 方式特有模块** — 章节结构统一，差异用选填模块表达
