# 请求材料健康管理与自动刷新产品方案

日期：2026-06-08
作者：方宜龙

## 1. 背景

小规模访问验证依赖已授权请求材料。历史方案把重点放在底层校验字段和采集手段上，普通用户难以理解，也容易误读为绕过平台访问控制。本方案改为产品化表达：系统只管理“请求材料是否可用、是否新鲜、是否覆盖目标城市、是否能形成证据”，不展示或生成任何敏感凭证材料。

## 2. 产品目标

- 让安全工程师知道哪些请求材料可用于验证，哪些已经过期或缺证据。
- 让运营和审核人员看到清晰状态：可用、即将过期、不可用、需要重新采集。
- 让系统在材料不可用时给出下一步：重新请求采集、补充授权窗口、切换同城材料或转人工确认。
- 让报告只展示脱敏摘要，不展示完整凭证、会话、认证字段和敏感响应。

## 3. 核心概念

| 产品概念 | 含义 | 展示方式 |
| --- | --- | --- |
| 请求材料 | 已授权会话中沉淀出的可复核请求样本 | 只展示来源、城市、类型和健康状态 |
| 材料健康 | 材料是否新鲜、是否能通过业务校验、是否能解析结果 | 健康、关注、失效、阻塞 |
| 城市覆盖 | 材料是否覆盖目标城市或地标 | 城市列表和覆盖率 |
| 请求预算 | 本次验证允许的低频访问次数 | 已用、成功、失败、剩余 |
| 网络出口 | 服务端访问目标平台时使用的受控出口 | 只展示出口类型和脱敏地址 |

## 4. 用户流程

```text
选择平台和城市
  -> 查看请求材料健康状态
  -> 系统提示是否需要重新采集
  -> 执行小规模访问验证
  -> 记录请求预算、业务响应摘要和入库结果
  -> 生成风控蓝军验证报告
```

当材料不可用时：

```text
材料不可用
  -> 判断原因：过期 / 城市不匹配 / 响应不可解析 / 网络出口异常
  -> 给出下一步：重新请求采集 / 补充授权窗口 / 换同城材料 / 转人工确认
  -> 记录处理过程和最终结论
```

## 5. 材料健康规则

| 检查项 | 健康 | 关注 | 不可用 |
| --- | --- | --- | --- |
| 新鲜度 | 最近采集，且近期验证成功 | 接近过期窗口 | 长期未更新或连续失败 |
| 城市匹配 | 返回数据属于目标城市 | 部分地标匹配不稳定 | 返回异地数据 |
| 业务校验 | 业务响应成功且可解析 | 偶发失败 | 连续失败或被平台拒绝 |
| 字段完整度 | 名称、地址、价格、枪数完整 | 个别字段缺失 | 核心字段缺失 |
| 证据完整性 | 请求摘要、响应摘要、入库结果齐全 | 缺少部分辅助证据 | 无法复核 |

## 6. 自动刷新策略

系统不尝试生成或猜测未知校验材料。刷新只来自已授权的请求采集过程。

| 场景 | 系统动作 | 人工边界 |
| --- | --- | --- |
| 材料即将过期 | 提醒安排请求采集 | 需要确认测试窗口 |
| 材料已失效 | 停止使用该材料并提示重新采集 | 不自动扩大访问范围 |
| 城市覆盖不足 | 推荐补采目标城市 | 不跨城市复用强绑定材料 |
| 响应不可解析 | 进入智能诊断，输出原因分类 | 不自动上线新解析规则 |
| 网络出口异常 | 标注出口失败并建议检查出口配置 | 不修改出口授权 |

## 7. 智能诊断能力

智能诊断只处理脱敏摘要，用于解释失败原因和推荐下一步，不接触完整凭证材料。

可自动判断：

- 材料过期或连续失败。
- 目标城市和返回城市不一致。
- 响应结构变化导致解析失败。
- 请求预算耗尽。
- 网络出口不可用或未命中。

必须转人工确认：

- 需要重新授权或重新登录。
- 需要新增平台解析规则。
- 需要改变网络出口策略。
- 需要处理完整凭证、会话或认证字段。

## 8. 报告展示

报告面向普通审核人员时，只展示：

- 平台、城市、地标和测试范围。
- 请求材料健康状态。
- 请求预算和成功/失败统计。
- 网络出口类型和脱敏出口地址。
- 业务响应摘要和字段完整度。
- 数据中心入库结果。
- 下一步处理建议。

报告不展示：

- 完整凭证材料。
- 会话材料和认证头。
- 完整业务请求地址和完整参数。
- 可用于绕过平台访问控制的实现细节。

## 9. 安全边界

- 不绕过登录、授权、验证码、证书固定或平台访问控制。
- 不生成未知平台校验材料。
- 不跨城市复用强绑定请求材料。
- 不把外部对照工具写成必需路径。
- 不把小规模访问验证包装成批量抓取能力。

## 10. 里程碑

| 阶段 | 目标 | 验收标准 |
| --- | --- | --- |
| M1 | 请求材料健康看板 | 能看到材料状态、城市覆盖、失败原因 |
| M2 | 自动刷新提醒 | 材料失效时给出重新请求采集建议 |
| M3 | 报告集成 | 报告能展示材料健康、请求预算和入库结果 |
| M4 | 智能诊断 | 常见失败能分类并给出下一步 |

## 11. 验收标准

- 普通用户不需要理解底层校验字段，也能知道材料是否可用。
- 材料不可用时，页面必须给出明确下一步。
- 所有证据默认脱敏。
- 高风险动作必须人工确认。
- 系统不能给出绕过平台访问控制的建议。
