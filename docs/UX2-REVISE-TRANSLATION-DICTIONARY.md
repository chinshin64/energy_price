## 一、术语翻译规则

### 1.1 检测标记术语（技术→业务语言）

| 技术标记 | 运营版翻译 | 管理层翻译 | 安全上下文标注 | 修正说明 |
|----------|-----------|-----------|--------------|---------|
| `missing_uid` | 无身份直达(IDOR风险) | 未经身份验证直达接口 | ⚠️ IDOR高风险 | ❗不能译为"未携带用户身份"，必须强调风险语义 |
| `missing_uid_anon` | 合法匿名访问(小程序等) | 正常匿名流量 | ✅ 已确认合法 | 与missing_uid严格区分，标注来源类型 |
| `ja3_many_uas` | 同一设备多身份标识 | 同一设备频繁切换身份 | ⚠️ 疑似身份伪造 | ❗"多身份标识"隐含伪造风险，不能只说"多UA" |
| `sig_multi_app` | 签名跨应用复用 | 凭证跨应用使用 | ⚠️ 疑似签名滥用/泄露 | 强调"复用"的异常性，非正常共享 |
| `enum_burst` | 批量资源遍历(枚举) | 大规模资源遍历攻击 | 🔴 枚举爆发 | ❗"枚举"不能降级为"探测"，至少"批量资源遍历" |
| `scan_probe` | 接口探测 | 接口扫描 | ⚠️ 侦察行为 | "探测"→"扫描"，语义更强 |
| `waf_token_probe` | 安全凭证探测 | 安全令牌试探 | 🔴 凭证窃取尝试 | 强调攻击意图 |
| `crawl_persistent` | 持续数据爬取 | 持续性数据抓取 | 🔴 恶意爬虫 | ❗"爬虫"不能弱化为"采集"，用"持续数据爬取" |
| `crawl_sequence` | 爬取行为链 | 数据遍历行为链 | ⚠️ 结构化爬取 | 强调序列性 |
| `high_freq` | 高频异常请求 | 请求频率异常 | ⚠️ 频率超限 | 需附带具体QPS数字 |
| `cross_day` | 跨天持续攻击 | 长期持续威胁 | 🔴 持久化威胁 | "跨天"→"持续"，管理层语境 |
| `score_anomaly` | 综合风险评分异常 | 行为异常 | ⚠️ 多维度风险 | 不单独使用，需附具体维度 |

## 二、百分比展示强制规则

### 2.1 核心规则：百分比必须附带绝对数字

**原则**：任何百分比出现时，必须同时展示分子和分母的绝对数字，禁止出现裸百分比。

| 场景 | ❌ 错误示例 | ✅ 正确示例 |
|------|-----------|-----------|
| 拦截率 | "拦截率96.3%" | "拦截率96.3%(1.62亿/1.68亿)" |
| IDOR风险占比 | "绝大多数请求正常" | "绝大多数请求正常(1827万/1893万)" |
| 误报率 | "误报率仅2%" | "误报率2%(387条/19350条)" |
| 签名覆盖率 | "覆盖率85%" | "覆盖率85%(17/20个应用签名)" |
| 爬虫占比 | "爬虫占比0.5%" | "爬虫占比0.5%(84万/1.68亿)" |

### 2.2 运营版关键数值折叠展示规则

运营版页面中，当数值超过3个时，默认折叠为摘要行，点击展开详情：

| 折叠项 | 折叠展示 | 展开内容 |
|--------|---------|---------|
| 威胁类型分布 | "3类活跃威胁，IDOR最突出" | 每类威胁的请求数、IP数、趋势箭头 |
| 告警统计 | "今日12条告警(P0×1)" | 按级别/类型/状态的详细分布 |
| 攻击者排行 | "TOP5攻击者，最活跃180.141.x" | 完整排行+威胁分值+行为摘要 |
| 签名状态 | "签名可用率92%(46/50)" | 各签名健康状态+失效列表+下次更新时间 |
| 基线偏差 | "2项偏离基线" | 偏离项+偏离幅度+建议动作 |
| 误报统计 | "近7天误报率2.1%(127/6048)" | 按规则类型拆分的误报率+绝对数字 |

### 2.3 管理层"未处理风险清单"子区域规则

管理层Dashboard中，态势评分下方必须展示"未处理风险清单"子区域：

| 字段 | 说明 |
|------|------|
| 风险等级 | 🔴紧急/🟡关注/🟢观察 |
| 风险描述 | 业务语言，如"getoneinfo接口存在无身份直达风险" |
| 影响面 | 绝对数字，如"1050万次请求/17天" |
| 置信度 | 高(已验证)/中(待确认)/低(需排查) |
| 当前状态 | 待处理/处置中/观察中 |
| 责任人 | 当前负责的运营/研发 |
| 持续时间 | 首次发现至今的天数 |

展示规则：
- 默认最多展示5条，按风险等级+置信度排序
- 紧急+高置信度排最前
- 点击风险条目→跳转至对应详情页
- 管理层只看摘要，不进入原始数据

## 三、置信度标注规则

### 3.1 管理层结论必须附带置信度

| 置信度等级 | 含义 | 标注方式 | 示例 |
|-----------|------|---------|------|
| 高(已验证) | 有明确攻击证据，经运营确认 | 🟢 高置信度 | "getoneinfo IDOR风险 — 高置信度，已验证1050万次无UID直达" |
| 中(待确认) | 检测规则触发，但需人工确认 | 🟡 中置信度 | "疑似签名跨应用复用 — 中置信度，dd05前缀跨2个应用" |
| 低(需排查) | 异常模式初现，需进一步分析 | 🔴 低置信度 | "新设备指纹出现 — 低置信度，需排查是否为新型攻击" |

### 3.2 运营版置信度展示

运营版页面中，每条告警/风险记录必须展示置信度标签，并附带判定依据：
- **高**：已关联到已知攻击模式或已人工确认
- **中**：规则触发但未被白名单覆盖，需运营确认
- **低**：新出现模式，历史数据不足

## 四、告警处置术语修正

### 4.1 处置操作改为组合操作

| 原设计(三选一) | 修正后(组合操作) |
|---------------|----------------|
| 误报/工单/封禁 互斥 | 误报+封禁+工单 可组合 |

修正后的处置操作语义：

| 操作 | 含义 | 组合规则 |
|------|------|---------|
| **标记误报** | 此告警为误报，豁免特定条件 | 可与"封禁"和"工单"同时选择 |
| **加入封禁** | 对相关IP/签名/设备执行封禁 | 可与"误报"和"工单"同时选择 |
| **创建工单** | 生成工单追踪此事件 | 可与"误报"和"封禁"同时选择 |

### 4.2 误报标记精确豁免规则

❗ **关键修正**：误报标记只豁免特定条件组合，不豁免IP全部行为。

| 豁免维度 | 说明 | 示例 |
|----------|------|------|
| IP+签名组合 | 仅豁免该IP使用该签名的告警 | 10.88.1.1+dd05前缀→豁免，但10.88.1.1+dd06前缀仍告警 |
| IP+接口组合 | 仅豁免该IP访问该接口的告警 | 10.88.1.1+/stationList→豁免，但10.88.1.1+/getoneinfo仍告警 |
| IP+规则类型 | 仅豁免该IP在该规则类型下的告警 | 10.88.1.1+枚举规则→豁免，但10.88.1.1+IDOR规则仍告警 |

❌ **禁止**：按IP全量豁免（"10.88.1.1全部告警标记误报"）

### 4.3 批量误报二级审批

| 场景 | 审批要求 |
|------|---------|
| 单条误报标记 | 运营直接操作 |
| 批量误报(2-10条) | 需另一运营确认 |
| 批量误报(>10条) | 需运营负责人+产品经理双审批 |
| 误报涉及P0告警 | 必须产品经理审批 |

## 五、误报率阈值差异化规则

| 规则类型 | 误报率阈值 | 说明 |
|----------|-----------|------|
| IDOR检测 | ≤2% | IDOR误报影响大(可能放过真实越权)，阈值严格 |
| 枚举检测 | ≤5% | 枚举模式相对清晰，允许略高 |
| 爬虫检测 | ≤5% | 爬虫与正常浏览边界模糊，适度宽松 |
| 签名滥用 | ≤3% | 签名误判影响业务签名正常使用 |
| 频率异常 | ≤5% | 频率基线波动大，允许略高 |
| 综合评分 | ≤3% | 整体控制线 |

## 六、3分钟巡检拆分规则

| 阶段 | 时间 | 内容 |
|------|------|------|
| **3分钟查看** | ≤3分钟 | Dashboard摘要+告警卡片+未处理风险清单 |
| **处置另计** | 按需 | 告警处理、封禁操作、工单创建等 |

展示规则：
- Dashboard顶部标注"巡检状态：✅ 已查看 / ⏳ 有待处置项"
- 有P0告警时，巡检状态强制显示"🔴 有紧急待处置"
- 处置时间不计入3分钟考核
