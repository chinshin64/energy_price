# 请求材料安全评估报告

> 分析日期：2026-06-08 | 适用范围：小规模访问验证的请求材料健康评估

## 1. 结论摘要

历史材料中包含平台校验相关内容，不适合在产品文档中展示底层字段、编码片段或生成方式。产品侧应把它们统一抽象为“请求材料”，只展示健康状态、城市覆盖、使用风险和下一步动作。

当前结论：

- 旧材料存在过期风险，不能直接作为长期可用能力。
- 跨城市复用材料存在误判风险，应按城市独立评估。
- 系统不应尝试生成未知校验材料。
- 请求材料刷新必须来自已授权的请求采集过程。
- 报告只展示脱敏摘要和复核结论。

## 2. 风险分级

| 风险 | 等级 | 产品表现 | 处理动作 |
| --- | --- | --- | --- |
| 材料过期 | 高 | 连续业务失败或无有效响应 | 停止使用并重新请求采集 |
| 城市不匹配 | 高 | 返回数据属于其他城市 | 禁止跨城市复用，补采目标城市 |
| 材料缺证据 | 中 | 只有结论，没有请求摘要或入库校验 | 标记为部分通过，补齐证据 |
| 字段缺失 | 中 | 地址、价格、枪数等字段不完整 | 进入复核或详情补全 |
| 网络出口异常 | 中 | 访问失败但材料本身未证伪 | 检查受控网络出口 |

## 3. 产品化表达

不再使用底层字段名作为主语。页面和报告统一使用以下表达：

| 旧表达问题 | 产品表达 |
| --- | --- |
| 底层校验字段失效 | 请求材料不可用 |
| 实时生成校验材料 | 重新请求采集 |
| 复用历史样本 | 使用已授权请求材料 |
| 底层还原或猜测 | 材料健康诊断 |
| 失败码分析 | 业务失败分类 |

## 4. 材料健康判断

健康材料必须同时满足：

- 来源可追溯。
- 城市和地标匹配。
- 最近验证成功。
- 请求预算内低频访问。
- 响应能解析为有效业务数据。
- 入库结果与响应摘要一致。
- 报告证据完整。

任一条件不满足时，报告不能写“通过”，只能写“部分通过”“失败”或“阻塞”。

## 5. 禁止事项

- 禁止展示完整凭证材料、认证头、会话材料或敏感响应。
- 禁止猜测或生成未知平台校验材料。
- 禁止跨城市复用强绑定材料。
- 禁止把外部对照工具写成主路径。
- 禁止把低频验证包装成无限访问能力。

## 6. 建议方案

短期：

- 把旧材料全部标记为待复核。
- 按城市重新建立材料健康状态。
- 请求失败时优先提示重新请求采集，而不是继续重试旧材料。

中期：

- 建立材料健康看板。
- 把材料状态写入风控蓝军验证报告。
- 对失败原因做结构化分类：材料过期、城市不匹配、网络出口异常、响应不可解析、字段缺失。

长期：

- 形成按城市、平台、材料类型管理的健康库。
- 将材料刷新纳入授权测试窗口。
- 建立人工确认和审计记录。

## 7. 报告模板

```text
请求材料评估结论：部分通过
适用城市：广州、深圳
健康状态：广州可用，深圳待重新采集
主要风险：深圳材料连续失败，疑似过期
证据完整性：请求摘要、响应摘要、入库校验齐全
下一步：重新请求采集深圳材料后复测
```

## 8. 安全说明

本报告只用于内部安全评估和产品设计，不提供平台校验材料的生成、还原或绕过方法。所有面向用户的页面和报告必须使用脱敏摘要。
